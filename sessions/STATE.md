### Архитектура и данные

- React 19 + Vite + TypeScript, Supabase (Postgres + Auth + RLS), без
  своего бэкенда. Шесть таблиц (`profiles`, `places`, `favorites`,
  `requests`, `routes`, `moodboards`), RLS-политики + общий триггер
  дневного лимита (1 анонимно / 5 зарегистрированным) на `places` и
  `requests`. 12 курируемых мест на старте (`app/supabase/seed.sql`),
  расширяется через `/add-place`.
- **DB-уровневые `CHECK`-ограничения** (добавлены на Task 8, агентом-
  ломателем найдено их отсутствие): `places.lat/lng` в допустимом
  диапазоне, `requests.comment` не пустой и ≤2000 символов,
  `routes/moodboards.place_ids` не пустой массив. Применены live через
  `alter table ... add constraint`, задокументированы в
  `app/supabase/schema.sql`.
- Общие модули с тестами: `lib/types.ts`, `lib/route.ts` (haversine,
  nearest-neighbor, URL-кодек), `lib/places.ts` (дедуп по радиусу),
  `lib/limits.ts` (текст ошибки лимита), `lib/mappers.ts` (единственное
  место snake_case→camelCase), `lib/authErrors.ts` (перевод известных
  сообщений Supabase Auth).
- Единый дизайн (`app/src/index.css`) — тёмная палитра, акцент
  «золотой час», подпись — угловые видоискатель-скобки на карте,
  активной навигации и карточках.

### Ключевые баги, найденные и исправленные за сессию

(Полная история — `git log`; здесь только классы багов, не дублируется.)

- **Обход дневного лимита** через `source:'curated'` с клиента —
  RLS-политика не проверяла `source`, исправлено (Foundation).
- **Неверное определение анонимности сессии** — `isAnonymousSession`
  читала не то поле (Foundation).
- **Падение общего триггера на вставке в `requests`** —
  `record "new" has no field "source"`, RECORD-типизация в общей функции
  на два разных триггера (найдено веткой requests-moodboard).
- **RLS-гонка после апгрейда анонимной сессии в постоянную** —
  `updateUser()` оптимистично обновляет объект пользователя раньше, чем
  JWT реально обновляется `refreshSession()`; более узкая версия той же
  гонки (событие `USER_UPDATED` обгоняет наш собственный `refreshSession()`)
  найдена повторно при написании golden-path — низкоприоритетно,
  не исправлено на уровне `AuthProvider`, тесты адаптированы ждать сетевой
  ответ, а не UI-состояние.
- **Мёртвые ссылки «Мои маршруты»** — `buildRouteUrl()` возвращает
  query-only ссылку, без `/` резолвится к текущему пути; исправлено при
  финальном ревью `feature/cabinet`.
- **Потеря данных профиля у вернувшегося пользователя** — `ProfileForm`
  мог смонтироваться до реальной загрузки профиля; исправлено флагом
  `initializing` в `AuthContext`.
- **Отсутствие DB-уровневых ограничений** (4 поля, 4 таблицы) — клиентская
  валидация была единственной защитой, обходилась прямым `curl`; найдено
  агентом-ломателем, исправлено `CHECK`-констрейнтами.
- **Дубли строк при быстром клике** на «Сохранить мудборд»/«Сохранить
  маршрут» — не было submit-guard'а, в отличие от `RequestForm`; найдено
  агентом-ломателем, исправлено.

## Известные проблемы

- Курируемых мест — 12 из ориентировочных ~40 из спеки; добавляются через
  `/add-place` по мере необходимости, не блокирует MVP.
- `RouteSummary` рендерится с нулевыми значениями, если старт задан, но
  места не выбраны — буквальный код плана, решение оставлено ревьюером
  как minor/plan-mandated.
- Отдельный список мест (`PlaceCard`, помимо маркеров карты) не построен
  — спека упоминала его как желательный, не обязательный вид.
- `extractAverageColor` не подключён к реальным пикселям (курированные
  места без `photo_url`) — коллаж рисует именные плашки. Осознанно
  отложено, подключить после появления реальных фото через `/add-place`.
- `cabinet-favorites.spec.ts` периодически падает под 4–6-воркерной
  параллельной нагрузкой на живой Supabase (`new row violates row-level
  security policy for table "profiles"`), но стабильно проходит в
  изоляции и на повторном полном прогоне — транзиентное ограничение живого
  проекта под нагрузкой, не регрессия кода, тест не менялся.
- «Мои маршруты» иногда пусты на первом рендере сразу после входа в уже
  существующий аккаунт с сохранёнными маршрутами (не после регистрации) —
  самоисправляется на reload. Найдено агентом-ломателем, причина не
  найдена за разумное время, честно оставлено как известная проблема.
- Демонстрация отказа песочницы (Codex, `docs/isolation-test-codex.md`)
  проверила shell и не-shell (`apply_patch`) пути самого Codex — не
  MCP-путь (у использованного Codex CLI не было живого MCP-подключения
  в той сессии). MCP-путь проверен отдельно, в Claude Code
  (`docs/isolation-test-mcp-claude-code.md`): та же MCP-сессия, что
  использовалась весь день для легитимной работы, получила отказ на
  первой же попытке — но от классификатора разрешений Claude Code Auto
  Mode, не от OS-уровневого sandbox, и похоже, что классификатор реагирует
  на заявленное намерение в разговоре, а не только на тип вызова (тот же
  вызов без слов «sandbox escape» в контексте проходил свободно). Одна
  точка данных, не исчерпывающая проверка — подробности в самом отчёте.
- Прогон инъекции недоверенного текста дал честный отрицательный
  результат: ожидаемого контраста «слабая/сильная модель» не получилось
  — обе распознали инъекцию (вероятная причина — сам сценарий явно
  маркировал границу доверия, см. `REPORT.md`).
