## Известные проблемы

- Курируемых мест — 12 из ориентировочных ~40 из спеки; остальные
  добавляются через `/add-place` по мере необходимости, не блокирует MVP.
- `RouteSummary` рендерится с нулевыми значениями (0.0 км, 0 мин, «Лёгкий»),
  если стартовая точка задана, но не выбрано ни одного места — так задано
  буквальным кодом плана (нет проверки `selectedPlaces.length` перед
  рендером), решение оставлено ревьюером как minor/plan-mandated, не
  блокирует MVP.
- Отдельный компонент `PlaceCard.tsx` / список мест (File Structure плана,
  спека §6 «…и в списке мест») ни одной задачей этого плана не построен —
  выбор и добавление в маршрут работают только через маркеры карты, без
  отдельного списочного вида; отложено на дизайн/интеграционный проход.
- `extractAverageColor` (мудборды) протестирован изолированно, но не
  подключён к реальным пикселям через offscreen `<canvas>` — курированные
  seed-данные не имеют `photo_url`, коллаж рисует плашки с именем места
  вместо усреднённого цвета. Осознанно отложено (задокументировано
  планом заранее), подключить после появления реальных фото через
  `/add-place`.
- **Наблюдение при интеграции (Task 1, полный `npm run test:e2e` с 4
  параллельными воркерами против живого Supabase-проекта):**
  `cabinet-favorites.spec.ts` один раз упал с `new row violates row-level
  security policy for table "profiles"` при полном параллельном прогоне,
  но стабильно проходит и в изоляции (`npx playwright test
  e2e/cabinet-favorites.spec.ts`), и при повторном полном прогоне (4/4
  зелёных). Похоже на транзиентное ограничение живого Supabase-проекта под
