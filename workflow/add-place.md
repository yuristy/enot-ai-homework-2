# Workflow: добавление нового места в каталог

Повторяемая процедура для безопасного расширения воспроизводимого каталога
`app/supabase/seed.sql`. Живая БД и git не изменяются без отдельного
подтверждения пользователя.

## Вход

- Фото (публичный HTTPS URL или локальный файл; для файла нужно решить, где
  получить публичный URL)
- Координаты (или адрес — тогда шаг 1 их найдёт)
- Короткое описание
- Теги (например: крыши, парки, граффити, архитектура, панорама)

## Промпт

```
Добавь новое место в каталог проекта "Москва в кадре".

Вход:
- Название: <название>
- Координаты или адрес: <lat,lng либо адрес>
- Описание: <короткое описание>
- Теги: <тег1, тег2>
- Фото: <файл или URL, если есть>

Сделай по порядку:
1. Проверь, что заполнены название, описание и теги. Координаты должны быть
   конечными числами в диапазонах lat [-90, 90], lng [-180, 180]. Не угадывай
   отсутствующие значения.
2. Если дан адрес, геокодируй одним одиночным запросом к публичному Nominatim:
   https://nominatim.openstreetmap.org/search?format=jsonv2&limit=3&countrycodes=ru&q=<encoded-address>
   Передай идентифицирующий User-Agent
   "MoscowInFrameHomework/1.0 (https://github.com/yuristy/enot-ai-homework-2)".
   Соблюдай https://operations.osmfoundation.org/policies/nominatim/:
   максимум 1 запрос/с, без batch/autocomplete, повторный результат используй
   из текущей сессии. Если сервис недоступен или результат неоднозначен —
   остановись и попроси пользователя выбрать/дать координаты; не угадывай.
3. Убедись по результату Nominatim/адресу, что место относится к Москве.
   При сомнении остановись и спроси.
4. Проверь дубликаты по app/supabase/seed.sql в радиусе 100 м через
   haversineDistanceKm из app/src/lib/route.ts. Если найдены — покажи название,
   координаты и расстояние каждого, затем спроси, добавлять ли всё равно.
5. Для фото принимай только публичный HTTPS URL. Если дан локальный файл и
   публичного URL нет, предложи сохранить photo_url = null либо остановиться —
   не придумывай URL и не добавляй data:/file: значение.
6. После существующего multi-row INSERT добавь отдельный валидный statement:
   insert into public.places
     (name, description, lat, lng, tags, photo_url, source)
   values
     ('...', '...', 55.0, 37.0, array['tag'], 'https://...', 'curated');
   Экранируй одинарные кавычки в SQL как ''. Для отсутствующего фото используй
   null без кавычек. Не изменяй created_by и не вставляй секреты.
7. Пересчитай curated rows в seed и обнови фактический счётчик в README.md.
8. Проверь git diff --check и запусти targeted unit test логики дубликатов.
   Покажи diff, рассчитанные расстояния и результаты проверок.
9. Спроси отдельное подтверждение перед commit и отдельно перед применением в
   живом Supabase. Без подтверждения остановись на проверенном diff.
```

## Формат

Этот файл — копируемый промпт. Тот же процесс доступен как скилл
`.claude/skills/add-place/SKILL.md`, вызывается `/add-place` в Claude Code.

Публичный Nominatim работает на пожертвованной инфраструктуре: workflow
разрешает только единичный пользовательский lookup, требует идентифицирующий
User-Agent и запрещает batch/retry-loop. Политика может меняться — перед
реальным вызовом агент повторно открывает ссылку из шага 2.
